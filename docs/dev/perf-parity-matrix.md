**Maintenance protocol.** This matrix is hand-maintained and therefore rots — the same failure mode as the CI shard list before `check-shard-coverage.sh`. Two defenses: (1) any chunk that adds or extends a performance technique MUST update its row in the same PR (the CLAUDE.md working agreement), and (2) the `perf-parity-checker` agent re-derives the matrix from code on demand and reports drift — run it after perf chunks land and before releases. A cell that is deliberately absent must say so and cite the rationale (ADR/bug/comment); an uncited ABSENT is presumed accidental and belongs on the gap list below.

Modes: **MIG** migrate bulk-copy · **CS** sync cold-start (per source flavor) · **BK** backup write · **RST** restore (full) · **CR** chain-restore incremental replay · **BRK** broker/from-backup replay · **CDC** steady-state apply.

Some shipped commands are not one of those seven — `backup export-as-parquet`, `backfill`, `expand-contract`, `backup compact`, `backup verify`. They still get a row (21–24, 29, 31), filed under the closest column with the rest `n/a`, because a command with no row is a command whose posture nobody is checking; that is what rows 21–24 were added to prevent and why `backup compact` and `backup verify` joined them on 2026-08-05.

Row 32 is a different axis from the rest and is stated so it is not mistaken for one: every other row prices a COPY technique, and row 32 prices what a run pays BEFORE the copy — the per-namespace preflight connections and catalog reads. It was added 2026-08-07 because there was no such row, and the absence is exactly how two target connections per database on both fan-outs went unnoticed.

## Observability overhead on the copy path (v0.148.0)

Not a throughput technique, recorded here because the pre-release perf-parity trigger asks for it and because the cost is real. The sync cold start now writes per-table progress rows so `sync status` can see a run that has not yet written its CDC anchor (2026-09-08 user report). `writeTableProgress` sits inside the **per-batch** copy loop, so the naive wiring added one synchronous control-table round trip per batch per table to **CS**, a mode that previously wrote nothing there — worst on exactly the cross-region, RTT-bound copies the feature exists to make legible.

It is bounded rather than absorbed: intermediate writes are throttled per table to one per 2s (`progressThrottle`), with terminal states and each table's first write exempt so status stays truthful. **MIG is deliberately NOT throttled** — there the same row is a `--resume` cursor, and coarsening it would widen the replay window on every interrupted migration, which is a correctness cost wearing a perf saving's clothes. The asymmetry is the point; do not "unify" these two without re-reading that.

Unreached by design: **BK / RST / CR / BRK / CDC** write no cold-start progress rows and pay nothing.

**Reach within CS, corrected 2026-09-09 (audit A0909-P2/P2b, `5b677120`):** the recording context is built ONLY by the PostgreSQL fast parallel cold-start path; every serial-copy source (MySQL/MariaDB/Vitess/PlanetScale binlog and VStream, SQLite/D1, the trigger engines) records nothing and pays nothing — the observability cost above is a PG-source cost, and the visibility it buys is PG-source visibility until P2b threads recording through the serial path's two branches. **SUPERSEDED 2026-09-10 — A0909-P2b SHIPPED, and this row now reaches every cold-start lane.** `runBulkCopyWithOpts` takes the recording context, so the cost and the visibility both extend to MySQL/MariaDB binlog, VStream/PlanetScale/Vitess, the three trigger engines, `--schema-already-applied`, the ADR-0072 resumable copy, the A0 client-copy fallback, and the multi-database fan-out (one recording for the whole fan-out, per-database progress keys). The BOUND is unchanged and is what keeps this affordable: the same `progressThrottle` governs every lane, so a serial lane pays at most one intermediate write per table per 2s plus its terminal write, on top of the same per-run `EnsureControlTable` round trip.
